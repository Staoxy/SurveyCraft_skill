# 问卷语言质量检查 Rubric（Agent 用）

本文件供 Agent 对问卷进行**语言层**审查时使用。结构层检查（选项重叠、量表一致性、
逻辑错误）已由 `survey_check.py` 完成，不要重复报告结构问题。

## 输出要求

- 每个发现输出一条 issue，写入 `outputs/review_report.json` 的 `issues` 数组（追加，
  不覆盖规则层已产出的条目）
- `source` 固定为 `"agent"`，`id` 使用 `ISS-A01` 起的编号，避免与规则层冲突
- severity 使用 `ERROR`（必须修，影响数据有效性）/ `WARNING`（建议修）/ `INFO`（提示）
- category 从下表的 category 列取值；每条必须给出 `message`（引用原文）与 `suggestion`（改写建议）
- **绝不允许直接修改问卷**，只报告与建议

## 检查项

### 1. 双重问题（double_barreled）— ERROR

一题同时询问两个概念，受访者可能对一个同意、对另一个不同意。

> 例：「AI 提高了你的学习效率并且让学习更加有趣。」

检查信号：题干中的「并且/而且/同时/也」连接两个独立判断；一个问句里出现两个不同的
评价对象。改写建议：拆分为两题。

### 2. 诱导性问题（leading）— ERROR

措辞暗示"正确"答案，或预设了受访者具有某种状态/态度。

> 例：「大多数同学都在用 AI 学习，你也认为它很有用吧？」
> 例：「你使用 AI 工具时遇到的最大困难是什么？」（预设受访者使用过且遇到困难）

检查信号：绝对化表述（总是/所有人都/公认）、情绪化形容、预设性提问（未筛选就问
"使用时……"）。

### 3. 歧义（ambiguous）— WARNING

指代不清或范围不明，不同受访者会理解成不同问题。

> 例：「你经常使用 AI 吗？」（"经常"未定义频率）
> 例：「你觉得它怎么样？」（"它"指代不明）

检查信号：未量化的频率词（经常/偶尔）、宽泛的指示代词、无时间范围的追问。

### 4. 复杂长句（complex_sentence）— WARNING

单句超过 ~40 字、多重从句嵌套，受访者难以在一次阅读中抓住重点。

### 5. 否定句 / 双重否定（negation）— WARNING

否定句降低可读性；双重否定极易误答。

> 例：「你是否不同意以下说法：AI 不适合用于学习？」

改写建议：改为直接肯定式提问。

### 6. 术语过难（jargon）— INFO

面向普通大学生/公众的问卷不应假设专业术语知识（如"信效度""认知负荷"）。若目标
群体就是专业人员，可降级或忽略。

### 7. 题目与构念不符（construct_mismatch）— WARNING

题目声称测量某 construct（schema 中的 `construct` 字段），但措辞实际指向另一概念。
例如 construct 为「满意度」，题目却在问「使用频率」。

### 8. 选项与题干不匹配（option_mismatch）— WARNING

选项尺度与题干问法不一致：题干问"是否"，选项却是程度；题干问"什么渠道"，选项却是
频率。

## 工作流程

1. 读取 `outputs/review_report.json`（规则层结果）与 `survey.json`
2. 逐题检查上述 8 项；每个 construct 的所有题目合起来通读一次，检查构念覆盖是否完整
3. 追加 agent issues → 保存 → 汇总一份人读版审查摘要（按 severity 分组）呈给用户
4. ERROR 未清零前，不应进入导出阶段（Gate 规则见 SKILL.md）
